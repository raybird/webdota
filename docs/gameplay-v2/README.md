## 背景與現況（2026-11-10 盤點）

| 面向 | 現況 | 問題 | 對應功能 |
|---|---|---|---|
| 操作 | WASD 與方向鍵依畫面方向移動；`1`～`4` 放技能、`Q` 也能放技能 1、空白鍵或 `0` 普攻 | 提示寫 `W / 2`、`E / 3`、`R / 4`，但 W 是移動、E 和 R 沒作用；手機也顯示按鍵提示 | F1 |
| 受擊範圍 | 英雄和小兵都是 0.6×0.6、高 1 的方塊，跟著面向旋轉 | 只有外觀寬度的 37%～55%，畫面打到卻判定落空；斜站時寬度會變 | F2 |
| 技能判定 | 立即判定的圓心在施法者前方 1 單位；火球以中心距離 < 1.3 判斷命中 | 打周圍的技能打不到身後；投射物不看目標體型 | F2、F3 |
| 回血 | 只有裝備 `hpRegen`（+2、+10/秒），由 Host 計算 | 沒有基礎回血、沒有泉水 | F4 |
| 地圖 | `demo_arena` 60×60，每隊 2 塔 1 主堡，小兵直線衝主堡 | 約 12 秒走到敵方主堡，迷霧與草叢沒有空間 | F5 |
| 移動碰撞 | `MovementSystem` 直接設定位置，沒有碰撞，也不限制在地圖內 | 從程式推斷可以穿牆、走出地圖（待實機確認） | F5 |
| 等級 | 沒有；成長只靠金幣（最後一擊：英雄 200、小兵 40、塔 150）買裝備；復活固定 5 秒 | 沒有成長節奏，大招開局就能用 | F6 |
| 視野 | 全圖互相可見 | 沒有資訊差與埋伏 | F7 |
| 人數 | 房間不限每隊人數，出生點依人數錯開 | 已可 1v1～3v3，但數值沒依人數設計 | F6 |

其他基準數值：英雄 1000 HP、防禦 10、移動速度 5，傷害為「攻擊傷害 − 防禦（最少 1）」；小兵每 30 秒一波、每波 3 隻、200 HP。

## 目標與非目標

**目標**
1. 一場在 **5～10 分鐘**內結束。
2. 同一張地圖支援 **1v1、2v2、3v3**，靠經驗平分等規則平衡。
3. 技能**好命中**：外觀、受擊範圍、技能範圍一致。
4. 加入**視野與草叢**，製造資訊差與偷襲機會。
5. 手機與桌機共用同一套操作邏輯，手機版面維持現狀。

**非目標**（本次不做）：回城、魔力、眼、滑鼠瞄準、依玩家過濾狀態的防作弊視野、多張地圖選擇與兩路模式、人數不對稱的自動平衡。

## 跨功能：網路同步與 Host 權威

| 項目 | 誰計算 | 同步方式 | 功能 |
|---|---|---|---|
| 回血 | Host | 現有 GAME_STATE 的 hp | F4 |
| 脫戰計時 | Host | 不同步；Host 遷移時重新計時 | F4 |
| 等級、經驗 | Host | GAME_STATE 每位玩家新增 level（Uint8）、xp（Uint16） | F6 |
| 大招解鎖 | Host 判定、Client 顯示 | 依同步的 level；Host 拒絕未解鎖的大招 | F6 |
| 建築無敵（前塔未破） | Host | 由 ENTITY_STATE 的存活狀態推得 | F5 |
| 移動碰撞 | Host 權威、Client 預測 | 兩端同一套碰撞；差距大時沿用現有拉回 | F5 |
| 視野、草叢 | 各 Client | 不同步，各自依收到的位置計算 | F7 |

GAME_STATE 格式變更後新舊版本無法互連：建房時檢查版本，不一致就提示重新整理。Host 遷移時，新 Host 沿用最後收到的 level、xp。

## 驗證方式

- **單元測試**（vitest）：命中判定、回血、經驗與等級、視野計算等純邏輯。
- **建置**：`npm run build`（含 `vue-tsc`）。
- **截圖**：headless Chrome 以 844×390、640×360（觸控）與 1280×720 截圖。本機注意：
  - 取消 `DISPLAY`（`env -u DISPLAY`）並加 `--ozone-platform=headless`，否則 WebGL 無法啟動。
  - `vite` 開發伺服器因檔案監看額度不足（ENOSPC）起不來時，改用 `npm run build` 加 `vite preview`。
- **雙分頁對打**：一個 Host、一個 Client，確認同步、命中、Host 遷移。
- **實機**：每個里程碑部署後用手機實際打一場。

## 風險與對策

| 風險 | 對策 |
|---|---|
| 地圖放大後鏡頭看到的範圍太小 | 視需要調整鏡頭高度；小地圖顯示視野內的敵人 |
| 移動碰撞讓 Client 預測與 Host 不一致 | 兩端同一份碰撞邏輯（`MapCollision`）；保留拉回機制。M3 雙分頁實測：撞主堡、外牆後兩端位置相同，移動中差約 0.35 |
| 視野計算拖慢手機 | 每 0.1 秒計算一次、只算友方單位；必要時降低解析度 |
| 等級曲線在 3v3 太慢 | 依實測調整被動與擊殺經驗 |
| 一場超過 10 分鐘 | 視需要加入後期機制（見待決事項） |
| GAME_STATE 格式變更造成新舊版本互連失敗 | 建房時檢查版本 |
| ~~Client 自己的英雄被小擊退（2 以內）時畫面不動，與 Host 位置最多差 2（M1 實測發現，改版前就存在）~~ | M3 已修（D22）：GAME_STATE 帶擊退次數，Client 看到變化就拉到 Host 的位置 |
